# Procedural HDR video fixtures

These are mathematical 24-frame pictures and declared synthetic metadata, under GPL-3.0-only. No supplied licensed movie, disc or private sample is included. `manifest.json` records every original file hash, actual tool binary/version and complete command recipe. Tool paths in the recipe are parameter names, not downloaded executables.

`base-pq.hevc` and `base-hlg.hevc` are 320x180 10-bit test patterns, with their respective PQ/HLG VUI. `dv-8.1.hevc` and `dv-8.4.hevc` add metadata generated by the official dovi_tool CLI. The 160x90 gray enhancement image and the generated profile-7 MEL/FEL RPU fixtures form `joined-MEL.hevc` and `joined-FEL.hevc` through the official CLI mux. These exercise real BL and EL coded pictures, NAL framing, B-frame reordering, metadata and base-picture preservation. The FEL image is **not** a mastered residual and does not prove FEL reconstruction or perceptual fidelity.

`hdr10plus.hevc` contains 24 actual SMPTE2094-40 SEI records with two 12-frame scenes. The official hdr10plus_tool inject/extract round trip retains every declared field and scene boundary. FFmpeg exposes HDR10+ side data on every decoded frame. The mastering display, content-light and luminance numbers are synthetic declared values, not measurements of the generated pixels or a real mastering display.

Annex B has no authoritative container PTS/DTS. The encoded VUI and 24-frame recipe do not establish a container duration. The separate C roundtrip test authors a test MP4 clock from actual HEVC POC, including B-frame reordering and one variable presentation interval. It then consumes that MP4's actual configuration and timestamps through `dovi_profile=mode=2`. Tests check all 24 packet timestamps/flags, `dvh1` profile8/compatibility1/no-EL configuration, unchanged base VCL bytes and decoded base pictures, and byte-identical converted RPU versus the official CLI mode2 oracle. This is real encoded-video repackage qualification, not a production separate-PID disc join.

Profile 5 RPU parser fixtures remain in `../dovi-metadata`. A PQ/HLG base must not be relabelled as profile 5: IPT-PQ image encoding and its output proof remain separate work. These fixtures also do not qualify physical displays, HDR10+ rendering, canonical HW1, other targets, disc scan/title/playback integration or remote reading.

Generate into an empty scratch directory with `scripts/generate-hdr-video-fixtures.py --encoder ENCODER --ffmpeg FFMPEG --ffprobe FFPROBE --dovi-tool DOVI_TOOL --hdr10plus-tool HDR10PLUS_TOOL --output OUTPUT`. Inputs are explicit existing tools; the script neither downloads nor builds them. The supplied encoder must have libx265 and lavfi testsrc2/color; the verifier must have HEVC decoding, rawvideo/framemd5 and the necessary demuxers.

Compile `third_party/ffmpeg/tests/dovi-video-roundtrip.c` with `cc -std=c11 -O2 -Wall -Wextra -Werror` and the exact tested prefix's `pkg-config --cflags --libs --static libavformat libavcodec libavutil dovi`. Run `scripts/qualify-hdr-video.py --fixtures fixtures/video/hdr-generated --scratch EMPTY_SCRATCH --ffmpeg FFMPEG --ffprobe FFPROBE --dovi-tool DOVI_TOOL --roundtrip-binary BINARY`. The FFmpeg build needs HEVC/MOV demuxing, MP4/HEVC/rawvideo/framemd5 muxing, HEVC parser/decoder, rawvideo encoder, `hevc_mp4toannexb`, and the checked `dovi_profile` BSF. No server capability is enabled by this test.
