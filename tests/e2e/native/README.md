# Android handheld E2E

Dispatch Android JVM tests with `handheld_e2e=true` to run independent Maestro
walks on hosted KVM phone and tablet emulators. Each device gets its own
local-only server on the same runner, accessed through `10.0.2.2`. The
`devtrust` owner hook avoids entering credentials. Do not upload server state
or generated credentials. Per-walk screenshots, video, JUnit, Maestro logs and
an aggregate result are retained for 14 days; each walk starts from cleared app
state and runs even if an earlier walk failed.

The walks exercise sign-in, Home, search, a title page, playback, a movie library,
settings and the subtitle panel. Playback observes two different time ranges;
the Arrival fixture is extended to 60 seconds for interactive checks. The
subtitle walk taps an English track, but visual selection and rendered subtitle
cues still require review. After those walks, the test API creates two fresh
owner profiles: one age-limited to PG-13, the other PIN-protected. Before the
profile walk, the API checks that Moon is indexed for the owner and hidden from
the restricted profile, and that Arrival remains visible. The device walk
captures the picker and PIN screen without entering a PIN, then checks allowed
and blocked search results under the restricted profile. This does not qualify
member sign-in, PIN submission, remember-profile or initial server setup: the
existing development hook seeds and signs in the owner only.

These captures are evidence to review, not automatic visual acceptance. Match
actual orientation, viewport and state before comparison; fixture content can
differ from the named mock title. Suggested frame bindings:

| Capture | Phone reference | Tablet reference, when the state and size match |
| --- | --- | --- |
| Welcome, local sign-in | auth#7 phone 4; local-sign-in frame needs confirmation | confirm matching frame |
| Home | phone-app#1 phone 1 | tablet#1b (landscape 1280 × 800 dp) |
| Search landing, results | phone-app#4 phones 7, 8 | tablet#10 (landscape, keyboard shown) |
| Title page | phone-detail#1 phone 1 | tablet#6 (landscape film) |
| Libraries overview, Movies | phone-app#3 phones 4d, 5 | identify matching state in tablet.html |
| Settings | phone-app#8 phone 16 | tablet#12 (landscape split view) |
| Picker, PIN | auth#15 phones 13, 14 | tablet#14 (landscape picker); confirm PIN frame |
| Player, subtitle panel | phone-player#1 phone 1 (sideways), #3 phone 3b (upright) | tablet-play#2 phone 2b (landscape) |

A reviewer must record separate works and matches verdicts, same-size reference
and captured images, and a checklist covering layout, sizing, type, color, art,
copy and visible controls. If the emulator viewport or state does not match the
reference, report matches as unverified and identify the missing capture; do not
scale a different layout into a pass. Send ambiguous frames and product calls to
the lead. No visual verdict is generated by the test itself.

A failed walk is evidence of failure, not automatically a product bug. Use
observable bounded waits. Keep the first failure; permit at most one fresh run
for diagnosis and report both outcomes. Quarantine only a reproduced intermittent
failure with a linked finding, owner and expiry; it must still run and report
independently and must not mask other tests or become required. Profile PIN
submission, member sign-in, fresh server setup, remember-profile, subtitle cue
rendering and the remaining gap-audit candidates need additional coverage.
