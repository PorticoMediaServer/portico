# Search profile authority

The writer and search preparation share this package. It owns the recipe name and the exact compiled profile; it imports neither one. `search.RecipeVersion` is an alias. Bank initialization reads the actual physical connection's SQLite version and source ID, compares them with `Compare(Compiled(), actual)`, and stores the three `Compiled()` fields only for a current native match.

`engine_version` is `sqlite/3.53.4;modernc.org/sqlite@v1.58.0;source_id/` followed by the exact source ID in `SQLiteSourceID`. `unicode_fingerprint` is `portico-search-profile-sha256-v1:` plus a lowercase SHA256. The hashed bytes are the algorithm name plus NUL, followed by eight UTF-8 strings, each prefixed with its unsigned 64-bit big-endian byte length: recipe, engine descriptor, actual compiled Go Unicode version, actual compiled x/text normalization Unicode version, x/text module and version, its module checksum, preparation-source digest, and native-format digest. No Go toolchain version, bank ID or research identity substitutes for these inputs.

The preparation pin covers the sorted production file closure listed in its test. Each file contributes a length-prefixed relative path, U64 big-endian token count, then length-prefixed token kind and literal for every Go token except EOF and comments. All semicolon literals are `;`; positions and formatting are excluded. The native pin covers the nine v1 native tables/content views listed in its test, in binary name order, as length-prefixed type, name and native declaration after the NUL-terminated native-format domain. Dependency pins, source closure, native engine and declarations are checked by tests.

A profile mismatch is derived search freshness, never a startup error or a new persisted phase. The server continues, accepts raw source invalidations, withholds incompatible normalized own/context/People/Reading hits, and schedules a governed rebuild and flip. A raw-title fallback needs a separately proved bounded path; otherwise search degrades clearly. Old images, token strings and unacknowledged receipts retain their custody. `Compatibility` is evidence, never permission to publish, reclaim or erase a receipt. Durable rebuild routing, native bank declarations and full source witnesses are separately reviewed contracts; this package adds no SQL or runtime wiring.
