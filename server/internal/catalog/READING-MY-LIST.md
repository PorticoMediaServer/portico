# Reading My List

An eligible normal selected profile can explicitly add/remove an actual ebook in a book library or comic in a comic library. The new My List endpoint uses the mark endpoint's independent normal-profile eligibility and original-principal same-transaction family/library/title guard, existing personal CAS and immutable operation receipts. A fresh response admission proof does not replace the stored membership result. It cannot set completion, resume, history, offline evidence, ratings or another field.

Saved includes those actual personal rows in its full visible predicate before shape/filter counts, anchor seek and LIMIT. Only libraries containing the viewer's visible saved Reading titles participate. Their accepted attribution generation/rule must be ready in the same snapshot; no false empty fallback is used. A bounded JSON set carries the actual library/generation/type pairs, avoiding a query expression per library. Its sorted generation witness binds the signed cursor. Requests without visible Reading saved rows retain the old cursor domain.

The selected page is projected through each actual Reading library's accepted metadata/primary-publication projection, then put back in the original server order. Ordinary entries retain their existing projection. Reading cards have their own ebook/comic identity, item-detail navigation, actual personal flags, availability, accepted publication type and ready selected cover. They have no playback target or audio duration. The ready-cover lookup is shared with the existing Reading projection and remains one IDs-bounded metadata query with no archive/provider acquisition.

In progress uses the latest original Reading observation, not AV seconds. The exact supported format, admitted current asset/inventory/root tuple, canonical lowest eligible observation and unchanged physical source revision must agree before the row enters the count/page predicate. The existing observation hash algorithm moved unchanged to a shared pure helper; the deterministic SQL function uses its same typed 14-field tuple. No database schema or saved-location write is added. The existing AV branch, sorting tuple, filter semantics and missing-value placement are retained. This source does not claim new Reading duration or cross-medium progress measurements.

New GET/PUT `/v1/items/{itemId}/reading/my-list` declarations use closed bounded membership/revision/operation models. Official artifacts are Release16-only. Source checks retain actual PDF/CBZ visible controls, profile isolation, immutable replay after a later opposite membership, actual Saved round-trip/counts/no playback, exact current-source In progress and stale-source exclusion, hidden title/library concealment, and unchanged Reading location.
