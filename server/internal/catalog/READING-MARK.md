# Explicit Reading completion

Reading detail's Mark as read action is a profile choice for an actual ebook in a book library or comic in a comic library. It is independent of publication classification and saved Reading location. It does not infer completion from page position, create a Reader session, or move the saved location.

The narrow catalog entry reuses the existing personal revision, immutable operation receipt, conflict and explicit watched-intent machinery. The general AV personal target predicate remains unchanged. The Reading entry can set only the boolean completion mark; no resume seconds, offline evidence, conflict resolution, rating, favorite or My List intent enters it. The AV explicit-resume side effect is bypassed only for this Reading entry.

GET/PUT `/v1/items/{itemId}/reading/mark` use the original principal, current family/library/title visibility and exact item inside the same personal read/write transaction. Both the catalog kind/library pair and the authorization callback are mandatory. Shared identity.CanUsePersonalState separately requires a normal selected owner/admin/member profile, nonempty authority/account/profile and no restricted grant; it is checked for the captured actor and again for the same-Tx rehydrated original principal before personal access. Browse success alone never supplies this eligibility. PUT retains the existing personal-write capability, bounded request, profile rate limit, operation ID and expected revision; GET uses the existing read capability. After mutation, the original principal is freshly readmitted and the captured viewer fence must agree, but that proof never replaces the stored operation result: replay returns the original read/revision even after a later contrary mark. Hidden and absent targets share the common concealed response.

The public model contains only server identity, viewer fence, exact item identity, boolean read mark, safe revision and (on a successful write) the echoed operation ID. It exposes no progress, archive bytes or playback grant. Official route/response artifacts belong to the next authorized Release checkpoint; no generation or item execution accompanies this source change. The detail consumer and My List integration are separate remaining source work, not credited by this producer alone.
